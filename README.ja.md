# go2rtc-viewer — ローカル防犯カメラビューア

RTSP / ONVIF に対応した任意の IP カメラの映像を、ブラウザで再生できるよう配信する、LAN 内専用のローカルビューアです。多くの IP カメラが配信する **H.265 (HEVC)** はブラウザで直接再生できないため、[go2rtc](https://github.com/AlexxIT/go2rtc) と `ffmpeg` を使って `H.265 → H.264` 変換を行い、WebRTC でブラウザに低遅延配信します。

カメラが既に H.264 を配信できる場合は変換不要で、`rtsp://` を直接指定できます（CPU 軽量）。自宅の防犯カメラを LAN 内のブラウザから手軽に確認する用途を想定しています。

> **⚠️ セキュリティに関する重要な注意があります。必ず [セキュリティ警告](#セキュリティ警告必読) を読んでください。**

## 概要

| 項目 | 内容 |
| --- | --- |
| 対象カメラ | RTSP / ONVIF に対応した任意の IP カメラ |
| 映像コーデック | H.265 / HEVC（多くの機種）または H.264。メイン（高解像度）/ サブ（低解像度・軽量）の 2 系統が一般的 |
| 音声コーデック | カメラに音声があれば対応（例: PCMA / G.711） |
| 配信方式 | go2rtc 経由の WebRTC（フォールバックで MSE / HLS も利用可） |
| 変換 | H.265 配信時は `ffmpeg` により H.265 → H.264 トランスコード（H.264 配信なら変換不要） |
| 視聴範囲 | **LAN 内のみ**（インターネット公開は想定していません） |

ブラウザは H.264 + WebRTC で映像を受け取るため、追加のプラグインやアプリは不要です。`./start.sh` を実行すると go2rtc サーバーが起動し、**go2rtc 内蔵ビューア（`http://localhost:1984`）が自動的にブラウザで開きます**。デザインを整えた独自ダッシュボード（`web/index.html`）も同梱しており、任意で利用できます（[独自ダッシュボードの開き方](#独自ダッシュボードwebindexhtmlの開き方-任意) を参照）。

## 前提条件

- **macOS (Apple Silicon / arm64)**
- **`ffmpeg` が導入済み**であること。確認:

  ```sh
  command -v ffmpeg
  ```

  パスが表示されれば OK です。表示されない場合は [Homebrew](https://brew.sh/) で導入してください:

  ```sh
  brew install ffmpeg
  ```

- **go2rtc 本体の事前インストールは不要**です。初回の `./start.sh` 実行時に、Apple Silicon 向けのバイナリ（`go2rtc_mac_arm64.zip`）を公式リリースから自動取得し、リポジトリ内に配置します。
- カメラと同じ LAN に接続されていること（カメラの実 IP は `.env` の `CAM_IP` に設定します。下記「セットアップ（.env）」参照）。
- ブラウザは WebRTC 対応のもの（最新の Safari / Chrome / Firefox / Edge）。

## セットアップ（.env）

実際の IP・RTSP/DVR 資格情報は、git 管理外の `.env` にのみ置きます（コミットされる設定はすべてプレースホルダ）。

1. `cp .env.example .env`
2. `.env` を編集して実値を記入
   （カメラ: `CAM_IP`, `RTSP_USER`/`RTSP_PASS`, `CAM_PATH_SUB`/`CAM_PATH_HD`。録画機能を使う場合のみ: `DVR_HOST`/`DVR_USER`/`DVR_PASS`, `BIND_ADDR`）
3. `./gen-config.sh`              # `.env` から `cameras.json` を生成（git 管理外）
4. `./start.sh`                   # `.env` を読み込み go2rtc を起動（`go2rtc.yaml` の `${VAR}` を解決）
5. `python3 -m http.server 8000`  # ダッシュボードを使う場合。先に手順 3 を実行しておくこと
                                  # （`start.sh` も手順 3 を自動実行します）

録画機能を使う場合（`recordings/server.js` は `start.sh` では起動しません）:

```sh
node recordings/server.js     # server.js は内蔵ローダで .env を読み込みます
# もしくは: set -a; . ./.env; set +a; node recordings/server.js
```

**リポジトリ衛生 vs 実行時の秘匿性** … この仕組みは「共有されるコミット履歴に LAN 構成・資格情報を残さない」ためのものです。ブラウザは `cameras.json` を取得するため、カメラ IP は LAN 上の DevTools からは実行時に見えます。`.env` 化は IP をローカルビューアから隠すものではありません。

**go2rtc の置換構文（確認済み）** … go2rtc は `go2rtc.yaml` 内の `${VAR}` / `${VAR:デフォルト}`（**コロン1個**）を**プロセス環境変数**から解決します（`.env` を直接は読まないため、`start.sh` が `set -a; . ./.env; set +a` で export します）。シェルの `${VAR:-x}` 形式は使えません。

## 使い方

リポジトリのルートで以下を実行します。**パスは自動解決される**ため、どのディレクトリから呼んでも動作します。

**起動:**

```sh
./start.sh
```

- 初回のみ go2rtc バイナリを自動ダウンロードします。
- go2rtc サーバーが起動します（管理 UI 兼ビューア: `http://localhost:1984`）。
- 既定のブラウザで `http://localhost:1984` が自動的に開きます。ここでストリーム一覧（`cam1` / `cam1_hd`）を選んでそのまま視聴できます。

**停止:**

```sh
./stop.sh
```

- 起動した go2rtc プロセスを停止します。

> 起動後、カメラ映像がブラウザに表示されない場合は [トラブルシュート](#トラブルシュート) を参照してください。

### 独自ダッシュボード（`web/index.html`）の開き方（任意）

同梱の `web/` ダッシュボードは、複数カメラのタイル表示・SD/HD 切替・スナップショット保存・全画面表示に対応しています。`web/index.html` は `cameras.json`（リポジトリ直下）を読み込むため、**リポジトリのルートを配信ルートにして** `web/index.html` を開きます（go2rtc は起動したままにしてください）。

```sh
# リポジトリのルートで実行（別ターミナル推奨）
python3 -m http.server 8000
# → ブラウザで http://localhost:8000/web/index.html を開く
```

- ダッシュボードは映像とスナップショットを `http://localhost:1984`（go2rtc）から取得します。go2rtc を別ホスト/別ポートで動かす場合は、URL に `?go2rtc=http://<host>:1984` を付けるか、`cameras.json` に `"go2rtc": "http://<host>:1984"` を追加してください。
- 手軽に試すだけなら、この独自ダッシュボードは不要です。`http://localhost:1984` の内蔵ビューアだけで視聴できます。

### 画面レイアウト（1 / 2 / 4 / 6 分割）

独自ダッシュボード（`web/index.html`）は、ヘッダの **「画面分割」セグメント切替**で **1 / 2 / 4 / 6 画面** のタイルレイアウトを選べます。各ボタンは「分割を表すミニグリッド図＋数字＋"画面"」で表示され、何画面に分割するかが一目で分かります。複数カメラを同時に監視したいとき、1 台を大きく見たいときで使い分けてください。

| ボタン | 分割数 | グリッド配置 | 用途の目安 |
| --- | --- | --- | --- |
| **1** | 1 画面 | 1 × 1 | 1 台を大きく表示（玄関だけ等） |
| **2** | 2 画面 | 2 × 1（横並び） | 2 台を並べて比較 |
| **4** | 4 画面 | 2 × 2 | 標準の多台監視 |
| **6** | 6 画面 | 3 × 2 | 最大数を一覧（最大 6 ペイン） |

> **操作ガイド（ヘルプ）** … ヘッダ右端の **「? ヘルプ」** ボタンを押すと、各ボタン（画面分割 / 画質HD / 撮影 / 全画面 / カメラ選択）と表示の見方（LIVE / SD・HD / 接続状態）をまとめた凡例が開きます。各操作はアイコン＋日本語ラベル＋ツールチップでも説明されます。

**ペインごとのカメラ選択**

- 各ペインには、`cameras.json` に登録された **有効なカメラが順番に自動で割り当て**られます。
- 各ペイン上部の **ドロップダウン**で、そのペインに映すカメラを `cameras.json` のカメラ一覧から自由に選び直せます。同じカメラを複数ペインに表示することもできます（例: 1 ペインは SD、別ペインは HD）。
- **カメラ台数がペイン数より少ない**場合、余ったペインは「カメラ未割当」のプレースホルダ表示になります（ドロップダウンから後で割り当て可能）。

**SD / HD・スナップショット・全画面**

- レイアウトを変えても、各ペインで従来どおり **SD / HD 切替・スナップショット保存・全画面表示** が使えます。
- 既定では負荷の軽い **SD（サブストリーム）** で表示し、必要なペインだけ HD（メイン）に切り替える運用を推奨します。6 分割で全ペインを HD（高解像度）にすると CPU・帯域の負荷が大きくなります。

**設定の永続化（localStorage）**

- 選んだ **レイアウト（1 / 2 / 4 / 6）** と **各ペインのカメラ割り当て** はブラウザの `localStorage` に保存され、**ページを再読み込みしても復元**されます。
- 設定はブラウザ（オリジン）ごとに保存されます。別のブラウザや別ポートで開いた場合は別設定になります。リセットしたいときは、ブラウザのサイトデータ（localStorage）を消去してください。

**ストリームのリーク防止**

- ペインのカメラを切り替えたりレイアウトを縮小（例: 6 → 1）したりすると、表示されなくなった `<video-stream>` の WebRTC / WebSocket 接続は**停止・破棄**され、必要なペインだけが再接続されます。接続が開きっぱなしになってカメラ・go2rtc に負荷が残ることはありません。

### ストリーム管理ページ（`web/streams.html`）

go2rtc 標準の管理画面（`http://localhost:1984`）を、ビューアと同じデザインに刷新した管理ページです。ビューア／管理は両ページ共通の **「ビューア / 管理」トグル**（ヘッダ右）で行き来できます（管理ページの URL は `http://localhost:8000/web/streams.html`）。go2rtc の API（`:1984`）を読み書きするので、**通常運用では go2rtc 標準UI（`:1984`）をほぼ開かずに済みます**。

ヘッダ右側の操作は両ページで同じ並び（**接続状態 → 更新 → ビューア/管理トグル → ヘルプ**）に統一しています。ビューアはその左に「画面分割」を持ちます。

管理ページは **4つのタブ**で構成されます。

- **ストリーム** … ストリーム一覧（カード表示）。各ストリームの **視聴者数**・**ソース接続状態**・**コーデック**（H264/PCMA 等）・**ソース（資格情報は伏字化）** を表示し、約8秒ごとに自動更新。
  - 各操作: `視聴`（go2rtc プレイヤーで再生）/ `情報`（状態JSON）/ `プローブ`（メディア解析）/ `リンク`（各種URL一覧）/ `ネット`（接続経路図）/ `削除`。
  - **再生モード**（`WebRTC / MSE / HLS / MJPEG`）の選択を「視聴」リンクに反映（`localStorage` 保存）。
  - **ストリーム追加**: 名前とソースで実行中の go2rtc に即時追加（`PUT /api/streams`）。恒久化は下記「設定」タブまたは `go2rtc.yaml` への追記で。
- **設定** … `go2rtc.yaml` をブラウザ上で直接編集（`GET /api/config` で読み込み、`POST /api/config` で保存）。**コメントは保持**されます。保存は確認のうえ、反映には go2rtc の再起動が必要（ページから再起動でき、復帰まで自動でポーリングします）。誤編集に備え **「バックアップ」**（現在の設定を `.yaml` でダウンロード）も用意。
- **ログ** … `GET /api/log` を約3秒ごとにポーリングし、**レベル色分け・時刻・コンテキスト**で表示。レベル絞り込み・検索・新着順・コピーに対応。
- **ネットワーク** … go2rtc の接続経路図（`net.html`）を埋め込み表示（初回表示時に遅延ロード）。完全オフライン環境では図の描画に CDN を要する点に注意。

> 注1: このページは go2rtc とは別オリジン（`:8000`）から `:1984` の API を呼ぶため、`go2rtc.yaml` の `api.origin: "*"`（同梱済み）が必要です。
> 注2: 「設定」の保存は `POST /api/config`（生のテキストを逐語で書き込み＝コメント保持）に限定し、`PATCH`（再整形でコメント喪失）は使いません。go2rtc 本体（`:1984`）の UI・バイナリは無改変です。

## 仕組み（アーキテクチャ）

多くの IP カメラは H.265 (HEVC) を配信しますが、ブラウザは H.265 を直接再生できません。そこで go2rtc が間に入り、`ffmpeg` でリアルタイムに H.264 へ変換してから WebRTC でブラウザへ届けます。カメラが既に H.264 を配信できる場合は変換不要で、`rtsp://` を直接指定できます。

```
┌────────────────────┐     RTSP / H.265 (HEVC)      ┌──────────────────────────────┐
│  IP カメラ          │ ───────────────────────────▶ │  go2rtc (localhost:1984)     │
│  <camera-ip>:554   │   <main-stream-path> (メイン)  │  ┌────────────────────────┐  │
│  RTSP_USER/PASS    │   <sub-stream-path>  (サブ)    │  │ ffmpeg                 │  │
└────────────────────┘                              │  │ H.265 ──▶ H.264 変換    │  │
                                                     │  └────────────────────────┘  │
                                                     └───────────────┬──────────────┘
                                                                     │ WebRTC / H.264
                                                                     │ (8555 TCP/UDP)
                                                                     ▼
                                                       ┌──────────────────────────┐
                                                       │  ブラウザ                  │
                                                       │  localhost:1984 内蔵ビューア│
                                                       │  または web/index.html     │
                                                       │  <video> で H.264 を再生   │
                                                       └──────────────────────────┘
```

- **入力**: `rtsp://${RTSP_USER}:${RTSP_PASS}@${CAM_IP}:554/${CAM_PATH_HD}`（メイン／高解像度）/ `.../${CAM_PATH_SUB}`（サブ／低解像度）。RTSP のパスは機種ごとに異なります（後述の例を参照）。
- **変換**: go2rtc の `ffmpeg:` ソース指定で `#video=h264` テンプレートを使い、H.265 を H.264 にトランスコードします。**メイン・サブとも H.264 のソースのみを登録**しているため、ブラウザのどの再生方式（WebRTC / MSE / HLS）でも必ず H.264 を受け取れます（生の H.265 ソースは登録していません。登録すると MSE が H.265 を掴んで再生に失敗するため）。カメラが H.264 を配信できる場合は `ffmpeg:` を外し `rtsp://...` を直接指定できます（CPU 軽量）。
- **出力**: WebRTC（低遅延）。ブラウザが WebRTC を利用できない場合は go2rtc が MSE / HLS にフォールバックします。音声（例: PCMA / G.711）があれば WebRTC 経路で再生できます。
- **ポート**: 管理 UI / API = `1984`、WebRTC = `8555`（必要に応じて RTSP = `8554`）。

### メイン / サブ ストリームの切り替え

ビューア上のボタンで **メイン（高解像度）** と **サブ（低解像度・軽量）** を切り替えられます。

- **メイン (高解像度)**: 高精細だが CPU 負荷・帯域・遅延が大きめ。録画確認や詳細を見たいときに。
- **サブ (低解像度)**: 軽量で遅延が小さい。常時モニタリングや複数台同時表示に向いています。

go2rtc 側では、サブ用とメイン用をそれぞれ別ストリームとして定義しています。本リポジトリの既定では、**`cam1`（サブ／既定表示）** と **`cam1_hd`（メイン／HD 切替時）** です。`cameras.json` の各カメラに対応するストリーム名（`stream` = 既定、`stream_hd` = HD）が記述されており、ビューアはこれを参照して切り替えます。既定でサブを表示するのは、常時表示の負荷を抑えるためです。

## カメラの追加方法

カメラを増やす場合は、**(1) go2rtc.yaml にストリームを定義**し、**(2) cameras.json にビューア用のエントリを追加**します。
以下は、2 台目・3 台目のカメラ（`cam2` / `cam3`）を追加する場合の例です（IP・RTSP パスは実機に合わせて調整してください）。台数を増やす場合は同様に `cam2` / `cam3` … を追加していきます。

### 1. go2rtc.yaml にストリームを追加

`go2rtc.yaml` の `streams:` セクションに、サブ（既定）/ メイン（HD）の 2 つを追加します。H.265 のカメラはブラウザで直接再生できないため、`ffmpeg:...#video=h264` を経由させます（カメラが既に H.264 を配信できる場合は `ffmpeg:` を外し `rtsp://...` を直接指定可能）。本リポジトリの命名規則は **既定（サブ）= `camN`、HD（メイン）= `camN_hd`**（`cam1` / `cam1_hd`、`cam2` / `cam2_hd`、…）です。RTSP のパスは機種ごとに異なります。サブ側のみ音声（`#audio=pcma`）を付け、メイン側は負荷軽減のため音声を省略しています（音声はカメラに音声がある場合の任意指定です）。

RTSP のサブ／メインのパスは機種ごとに異なります。例:

| ベンダー | サブ（低解像度） | メイン（高解像度） |
| --- | --- | --- |
| ONVIF / 汎用 | `/stream2` | `/stream1` |
| Hikvision | `/Streaming/Channels/102` | `/Streaming/Channels/101` |
| Dahua | `/cam/realmonitor?channel=1&subtype=1` | `/cam/realmonitor?channel=1&subtype=0` |

```yaml
streams:
  # --- 既存: cam1（<camera-ip>） ---
  # 既定表示はサブ（軽量）。映像 H.264 +（カメラに音声があれば）音声 PCMA。
  cam1: ffmpeg:rtsp://${RTSP_USER}:${RTSP_PASS}@${CAM_IP}:554/${CAM_PATH_SUB}#video=h264#audio=pcma
  # HD（メイン／高解像度）。映像のみ H.264。
  cam1_hd: ffmpeg:rtsp://${RTSP_USER}:${RTSP_PASS}@${CAM_IP}:554/${CAM_PATH_HD}#video=h264

  # --- 追加例: cam2 ---
  cam2: ffmpeg:rtsp://${RTSP_USER}:${RTSP_PASS}@<camera-ip>:554/<sub-stream-path>#video=h264#audio=pcma
  cam2_hd: ffmpeg:rtsp://${RTSP_USER}:${RTSP_PASS}@<camera-ip>:554/<main-stream-path>#video=h264

  # --- 追加例: cam3 ---
  cam3: ffmpeg:rtsp://${RTSP_USER}:${RTSP_PASS}@<camera-ip>:554/<sub-stream-path>#video=h264#audio=pcma
  cam3_hd: ffmpeg:rtsp://${RTSP_USER}:${RTSP_PASS}@<camera-ip>:554/<main-stream-path>#video=h264
```

> **補足**
> - `#video=h264` は go2rtc 組み込みのトランスコードテンプレートです。映像を H.264 に変換します。カメラが H.264 を配信できる場合は省略でき、`rtsp://...` を直接指定すれば変換不要で CPU 軽量になります。
> - `#audio=pcma` は元の PCMA / G.711 を WebRTC 互換のまま渡します（PCMA は WebRTC で再生可能）。**カメラに音声がある場合の任意指定**です。音声不要・音声非対応なら `#audio` を省略してください（メイン側は省略しています）。
> - **生の H.265（HEVC）RTSP を同じストリームに併記しないでください。** go2rtc は消費者が受理できる最初のソースを使うため、HEVC を併記すると MSE などが HEVC を掴んで再生に失敗します。H.264 トランスコードのみを登録します。
> - **認証情報を直書きしたくない場合**は、[セキュリティ警告](#セキュリティ警告必読) の「認証情報の分離」を参照してください。

### 2. cameras.json にカメラを追加

`cameras.json` にビューア用のエントリを追加します。各エントリは `id` / `name` / `ip` / `stream` / `stream_hd` / `enabled` を持ちます。`stream` に既定（サブ）、`stream_hd` に HD（メイン）の go2rtc ストリーム名を指定します。`enabled: false` のエントリは無効化され、ビューアに表示されません。

```json
{
  "cameras": [
    {
      "id": "cam1",
      "name": "玄関",
      "ip": "${CAM_IP}",
      "stream": "cam1",
      "stream_hd": "cam1_hd",
      "enabled": true
    },
    {
      "id": "cam2",
      "name": "駐車場",
      "ip": "<camera-ip>",
      "stream": "cam2",
      "stream_hd": "cam2_hd",
      "enabled": false
    }
  ]
}
```

カメラを増やす場合は、上記の `cam2` を有効化（`enabled: true`）して `ip` を実値にするか、同様に `cam3` / `cam4` … を追加します。go2rtc.yaml 側にも対応する `camN` / `camN_hd` ストリームを定義してください。

変更後、`./stop.sh` → `./start.sh` で go2rtc を再起動すると反映されます（独自ダッシュボードはブラウザを再読み込みするだけで反映されます）。

## 録画（Playback）機能

> **この録画機能は塚本無線 OEM の DVR（XVR）専用の任意機能です。** 上記のライブ視聴は
> RTSP 対応の任意の IP カメラで動作し、**この録画機能には一切依存しません**。塚本無線 OEM の
> DVR を使っていない場合、このセクションは読み飛ばして構いません。

ライブ視聴に加えて、防犯 DVR（**塚本無線 OEM の XVR**, IP `<dvr-ip>`）まわりの
**録画の検索・ダウンロード・閲覧**機能を `recordings/` 配下に同梱しています。go2rtc
ライブビューア（ポート `1984`）とは**独立したバックエンド**（Node 標準モジュール +
`ffmpeg`）で、**別ポート `http://localhost:3914`** で動作し、両方を同時に起動できます。

> **重要 — このDVRの録画HTTP-APIは現行ファームで実用になりません（実機確認済み）。**
> DVR の netsdk 検索 `R.SearchRecord` は「成功」応答でも**常に 0 件**、録画DL用の
> `cgi-bin/flv.cgi` は**全パラメータで HTTP 404** です。同梱の netsdk / `flv.cgi`
> クライアント（`recordings/`）は**仕様準拠の best-effort 実装**で、別機種・別ファーム
> では録画一覧／DL に使えますが、**本機では一覧が返りません**。
> **本リポジトリには自動録画機能は同梱していません。** 録画を残したい場合は、go2rtc
> ライブと同じカメラの RTSP を `ffmpeg` で手動キャプチャしてください。
> 詳しい切り分けは [`recordings/README.ja.md`](recordings/README.ja.md) を参照してください。

### 起動と使い方

**起動**（リポジトリのルートから。go2rtc とは別プロセス・別ポートなので共存可能）:

```sh
node recordings/server.js
# → http://localhost:3914 を既定ブラウザで開く
```

- **Web UI**: `http://localhost:3914` で、チャンネルと日時範囲を指定して録画を検索 →
  ブラウザ内 `<video>` で MP4 再生 → ダウンロードできます（サムネイル付き）。
  ※本機の DVR ファームでは検索が常に 0 件を返すため、一覧は空になります（前述の注記参照）。
- **CLI**: DVR の録画検索・DL は `recordings/download-cli.js` で行えます
  （フラグは `--help` を正とします）。例:

  ```sh
  node recordings/download-cli.js --help                 # 使い方
  node recordings/download-cli.js --list                 # 当日の録画一覧（本機では 0 件）
  node recordings/download-cli.js --chn 1 \
    --begin "2026-06-04 00:00:00" --end "2026-06-04 23:59:59"   # 範囲を指定して DL を試行
  ```
  > `server.js` は Web UI 用のサーバで、サブコマンドは持ちません。

- **停止**: フォアグラウンド起動なら `Ctrl+C`。
- **設定（環境変数）**: `DVR_HOST`（DVR の IP / ホスト）, `DVR_USER`（既定 `admin`）,
  `DVR_PASS`（既定 空）, `BIND_ADDR`（待受。既定 `127.0.0.1` = localhost 限定）,
  `PORT`（既定 `3914`）。パスワードは**ソースに書かず**環境変数で渡します。

  ```sh
  DVR_PASS='********' PORT=4000 node recordings/server.js
  ```

### DVR 録画 API の要約（実機調査）

塚本無線 OEM の XVR（FW 3.2.2.6F）で確定した仕様の要点です（全文・移植の根拠は
[`recordings/README.ja.md`](recordings/README.ja.md)）。`<dvr-ip>` は DVR の実 IP に読み替えてください。

- **認証**: HTTP Basic 固定。`Authorization: Basic <base64("admin:")>`（PW 空）。
  誤 PW / 無 PW は **401**、`admin:` 空のみ **200**。`POST /login` も成功するが
  トークンは発行されない（Basic のみ）。
- **録画検索**: `POST http://<dvr-ip>/netsdk/R.SearchRecord`
  （`Content-Type: application/json`, Basic）。body は
  `{DEV:"XVR",VER:"1.0",API:"R.SearchRecord",Parameter:{...}}`。
  - `BeginTime`/`EndTime` は**フル日時 `"YYYY-MM-DD HH:MM:SS"`** 必須。時刻のみ・
    Unix 秒・空 `Parameter` は `Search Failed!`。`Reload:"True"` は**付けない**。
  - `Channel` は `MAX_CHN`(=9) 個の真偽配列（`"True"`＝検索対象）。`Type` は
    `{Timing,Motion,Alarm,Manual}`。録画 Item の時刻は **Unix 秒**、ch は **0 起点**。
  - **本機では成功応答でも `ReadCnt:"0"`・Item 無し**（2TB HDD 100% 使用・録画中でも 0 件）。
- **録画 DL**: `GET http://<dvr-ip>/cgi-bin/flv.cgi?...&chn=<ch>&begin=<UnixSec>&end=<UnixSec>...`
  → 設計上は時間範囲の FLV。**本機では全パラメータで 404**（`gw.cgi` も 404）。
- **構成取得に使える同系 API**: `/netsdk/Stat`（機器/HDD/IPC/録画状態が実データ・最重要）,
  `/netsdk/GetChannelDetail`（9ch 解像度）, `/netsdk/Record`（録画スケジュール）,
  `/netsdk/R.SEARCH.Ipc`（接続中 IPC＝ch0=`<camera-ip>`）, `/netsdk/LogSearch`,
  `POST /login`。`/netsdk/Channel` `/netsdk/General` 等は echo を返す SET 系テンプレで
  構成取得には使えません。
- **チャンネル**: 9ch 構成。実カメラは **ch0（UI 表示 ch1）のみ接続**＝`<camera-ip>`
  の IP カメラ（メイン・サブとも HEVC）。録画 / `flv.cgi` の ch は 0 起点。

### 録画機能のセキュリティ注意

ライブ視聴と同じ注意がそのまま当てはまります（[セキュリティ警告](#セキュリティ警告必読)）。
録画機能で特に重要な点:

- **DVR / カメラの `admin` / 空パスワードは危険**。必ず強固なパスワードを設定し、
  本機能には `DVR_PASS` 環境変数で渡してください。**ソースに直書きしない**こと。
- **録画出力（クリップ・サムネイル）には映像が含まれます。** `recordings/` のランタイム
  出力は `.gitignore` 済みですが、誤って公開リポジトリに含めないよう注意してください。
- 録画サーバ（`3914`）・DVR（`80`）・カメラ（`554`）を**インターネットに公開しない**
  こと。`127.0.0.1:3914` 限定運用を推奨し、外出先からは VPN 経由で。

## トラブルシュート

### 映像が出ない

1. **管理 UI で配信状態を確認**: ブラウザで `http://localhost:1984` を開き、`streams` に該当ストリームが表示され、再生できるか確認します。
2. **カメラに到達できるか確認**:

   ```sh
   ping ${CAM_IP}
   ffprobe "rtsp://${RTSP_USER}:${RTSP_PASS}@${CAM_IP}:554/${CAM_PATH_HD}"
   ```

   `ffprobe` でストリーム情報（コーデック / 解像度）が表示されれば、カメラ自体は配信できています。
3. **同一 LAN にいるか確認**: VPN や別セグメントに接続していると到達できません。
4. **認証 / パス**: RTSP のユーザー名・パスワード・ポート `554`・ストリームパスが実機設定と一致しているか確認します（パスは機種ごとに異なります）。

### 遅延が大きい

- **サブストリームに切り替える**: 高解像度のメインは負荷が高く遅延しやすいです。ビューアでサブ（低解像度）を選択してください。
- **WebRTC が使えているか確認**: WebRTC が確立できないと MSE / HLS にフォールバックし、遅延が増えます。WebRTC ポート `8555 (TCP/UDP)` がローカルで通っているか確認してください。
- **ハードウェアアクセラレーション（任意）**: トランスコードの負荷を下げるため、go2rtc.yaml の各ソース末尾に `#hardware=videotoolbox`（または自動検出の `#hardware`）を付与すると、macOS では VideoToolbox によるハードウェア支援を利用します。ただし go2rtc 公式によれば **Apple Silicon では CPU トランスコードの方が速い場合が多い**ため、まずは付けずに試し、CPU 負荷が高いときだけ有効化してください。不安定な場合は外します。

  ```yaml
  # 例: HD（メイン／高解像度）にハードウェア支援を付ける
  cam1_hd: ffmpeg:rtsp://${RTSP_USER}:${RTSP_PASS}@${CAM_IP}:554/${CAM_PATH_HD}#video=h264#hardware=videotoolbox
  ```

### ffmpeg が見つからない

- `command -v ffmpeg` でパスが表示されるか確認してください。
- 表示されない場合は `brew install ffmpeg` で導入します。
- go2rtc は `ffmpeg` を PATH から解決します。Homebrew の bin（Apple Silicon では通常 `/opt/homebrew/bin`）が PATH に含まれているか確認してください。

### ポートが競合する

go2rtc は既定で `1984`（API/UI）・`8555`（WebRTC）・`8554`（RTSP）を使用します。既に使用中の場合:

1. **使用中プロセスを特定**:

   ```sh
   lsof -i :1984
   lsof -i :8555
   ```

2. **ポートを変更**: `go2rtc.yaml` の `api` / `webrtc` / `rtsp` セクションでポートを変更します。

   ```yaml
   api:
     listen: "127.0.0.1:1985"
   webrtc:
     listen: ":8556"
   ```

   ポートを変えた場合、ビューア（`web/app.js` など）が参照する API ポートも合わせて更新してください。

## セキュリティ警告（必読）

このプロジェクトは **LAN 内の個人利用** を前提としています。以下を必ず守ってください。

### 1. パスワード未設定・初期パスワードのカメラは危険です

多くの IP カメラは出荷時に **`admin` / 空パスワード** や推測されやすい初期パスワードで設定されています。これは、

- 同じ LAN（および設定ミスで外部公開された場合はインターネット）から、**誰でも映像を覗き見・設定変更できる**状態です。
- 家庭内のプライバシーが第三者に流出する重大なリスクがあります。

👉 **カメラ管理画面から、推測されにくい強固なパスワードを必ず設定してください（強く推奨）。** パスワードを設定したら、`.env` の `RTSP_USER` / `RTSP_PASS` を実値に更新します（`go2rtc.yaml` の RTSP URL は `${RTSP_USER}:${RTSP_PASS}@` で解決されます）。

### 2. インターネットに公開しないこと

- このビューアと go2rtc は **LAN 内からのアクセスのみ** を想定しています。
- **ルーターのポート転送（ポートフォワーディング）や UPnP で `1984` / `8554` / `8555` 等を外部公開しないでください。**
- go2rtc の API は既定でローカルホスト（`127.0.0.1:1984`）に限定する構成を推奨します。LAN 内の他端末から見たい場合でも、信頼できるネットワークに限定し、ファイアウォールで保護してください。
- 外出先から見たい場合は、ポート公開ではなく **VPN（自宅 LAN への安全なトンネル）経由** を利用してください。

### 3. 認証情報の分離（推奨）

`go2rtc.yaml` に RTSP のパスワードを直書きすると、リポジトリ管理時に漏洩する恐れがあります。

- 認証情報は **環境変数や別ファイル（.gitignore 済み）で管理**することを推奨します。go2rtc.yaml では `${RTSP_PASSWORD}` のような環境変数展開を利用できます。
- 機密値を含むファイルは **コミットしない**でください（`.gitignore` で除外されているか確認）。

### 4. P2P / クラウド送信の確認

- 多くの中国製 IP カメラには、**P2P / クラウド機能** が搭載されており、設定によってはメーカーのサーバーへ映像や接続情報が送信されることがあります。
- **カメラの管理画面で P2P / クラウド / リモートアクセス機能を無効化** し、不要な外部通信を遮断することを強く推奨します。
- 可能であれば、ルーター側でカメラのインターネット向け通信をブロックし、**LAN 内に隔離**してください。
